# 한국어 표현 점검 (공통 문체 규칙)

한국어 글쓰기의 공통 규칙이다. `my-writing-blog`(블로그 톤)·`my-writing-book`(기술 도서 톤)이 이 스킬을 공통으로 참조하며, 단독으로는 임의의 한국어 글 퇴고 체크리스트로 쓴다. 초안 작성 시 지키고, 퇴고 시 체크리스트로 쓴다.

통계적 AI 패턴(쉼표 분포, 품사 다양성, 문장 리듬 등)의 정밀 스캔은 `humanizer` 스킬을 병용한다. 두 스킬의 규칙이 충돌하면 **이 문서(사용자 피드백 유래 규칙)가 우선**한다.

> 2026-08에 8월 포스트 전수 검토에서 나온 실제 지적들을 규칙화한 것.

## em dash(—) 금지

보충은 마침표로 끊거나 괄호로, 동격·부연은 콜론으로, 강조는 볼드로 처리한다. 코드 주석·각주·인용 원제까지 포함해 전수 제거하고 `grep '—'`로 0개를 확인한다.

## 기술 용어: 축자 번역도, 어색한 음차도 금지

- **영어 기술 관용어를 축자 번역하지 않는다.** 실제 지적 사례: layer→"겹", knob→"손잡이", (code) hygiene→"위생", copy→"부"(앱 한 부), cheap failure→"싼 실패", buys nothing→"돈이 사는 건 없다". 통용되는 음차(레이어, 스크레이프)나 자연스러운 우리말(설정값, 뒷정리, 비용이 거의 들지 않는)을 쓴다.
- **통용도 낮은 음차·반쪽 음차 금지.** 사례: 키잉(keying), 트라이(trie), 목(mock→"모의"), 랩(lab→"실험 환경"), 퍼-HPA(per-→"HPA별"), 노이즈 이웃(noisy neighbor→"시끄러운 이웃(noisy neighbor)"). 판단 기준은 "한국 개발자 글에서 흔히 보는 표기인가".
- **낯선 용어·비유어는 첫 등장에서 병기한다.** `백스톱(backstop, 안전장치)`, `함대(fleet, 서비스의 전체 파드 무리)` 식으로. 병기 없이 반복 사용하지 않는다.
- **한 글 안에서 같은 개념을 두 말로 부르지 않는다.** 사례: 같은 문단에서 "긁고"와 "스크레이프", 글 전반의 "처리량 천장"과 갑자기 등장하는 "cliff". 첫 등장에서 병기로 묶고 이후 하나로 통일한다.

## 번역투 문형 금지

- **무생물 주어 + 행위 동사**: "그 돈이 사는 건 아무것도 없다" → "그 돈으로 얻는 것은 아무것도 없다". "그 이야기는 짚으며 돌아온다" → "~할 때 다시 나온다".
- **독자를 "너"로 부르지 않는다**: "너는 노드 값을 낸다" → "돈은 노드 값으로 나간다".
- **영어 명사구 축자 나열 금지**: "단일 최고 레버리지 비용 절감" → "레버리지가 가장 큰 단일 비용 절감 수단".
- **부사+형용사 직역 금지**: "일부러 완전한 이미지"(deliberately complete) → "의도적으로 완전하게 만든 이미지".
- **부정의 위치**: "아무것도 바뀌었다고 느끼지 않는" → "아무것도 바뀌지 않았다고 느끼는". 부정은 종속절에 둔다.
- **논항 확인**: "프로세스에게 세계를 속이다"처럼 동사의 조사 구조가 어긋난 문장을 쓰지 않는다.

## 어휘·연어

- 헷갈리는 쌍: 반복 측정은 **횟수**(회수 아님), 정당한 이유는 **명분**(명목 아님), 형벌 은유는 **형(刑)**(행 아님).
- 관념어 지양 (2026-08-15 피드백): "층위" 같은 학술적 관념어를 쓰지 않는다 ("평소에 있어도 되는 층위" → "평소에는 서로 몰라도 되는 영역"). 사용자가 일상적으로 쓰는 말(영역, 부분, 지점)로 푼다.
- "처방" 금지 (2026-08-16 피드백): 해결책을 "처방"이라 부르지 않는다. "해법"으로 쓴다.
- 부사 중복 금지: "유일하게 고유하게" 같은 동의어 겹침.
- "아무 + 명사 + 가"는 비문: "아무 건강한 워커가" → "살아 있는 워커 중 하나가".

## 두 번 읽게 만드는 문장 금지

- **동음이의어 오독**: "실명"(失明/實名), "절도"("절 + 도"가 竊盜로 읽힘), "행"(行/刑)처럼 첫 독해가 갈리는 단어는 한자 병기, 어순 변경, 다른 단어로 회피한다.
- **수식 순서**: "죽은 직전 컨테이너" → "직전에 죽은 컨테이너". 수식어가 어디 걸리는지 한 번에 읽혀야 한다.
- **관계절 오독**: "**폭발 반경과 롤아웃 단위**가 작은 파드는~"처럼 볼드 리드가 뒤 문장의 주어에 붙어 읽히는 구조를 피한다.
- **은유는 첫 등장에서 세운다**: "실명 절이다"처럼 비유를 정의 전에 준기술용어로 쓰지 않는다. 비유가 깔리지 않은 글에서 다른 글의 은유를 가져오지 않는다.
- **압축 조어 금지**: "4동시" → "동시성 4". "p90에서 피크" 같은 중의적 결합은 "피크 시간대 실사용량의 p90"으로 푼다.
